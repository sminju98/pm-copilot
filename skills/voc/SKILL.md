# voc — 고객의 소리 → 인사이트 → 기획 (+ 미응답 추천 답변)

VOC를 읽기만 하면 쌓이는 로그다. 여기선 **분석하고, 인사이트를 뽑고, 기획으로 잇고, 미응답엔 답까지** 쓴다.

## 1. 수집 (기존 채널 점검)
- 커넥터(Intercom·이메일·스토어 리뷰·설문·시트)에서 VOC를 모은다. 미연결이면 붙여달라 하거나 "확인 필요".
- **개인정보는 익명화**, 결과물에 PII를 남기지 않는다(데이터 경계).

## 2. 분석 → 인사이트 (그냥 목록 X)
- 테마별로 묶고 **빈도·심각도·세그먼트** 표기, 대표 인용 1~2개([[research-synthesis]] 방식).
- "불만 목록"이 아니라 **왜 생기나 + 무엇을 의미하나(so what)**. 지표([[metrics-watch]])와 교차 — VOC가 지표로도 보이나.

## 3. 기획으로 연결
- 임팩트 큰 테마 → [[prioritize]] → 개선 [[write-spec]] → [[project]] 태스크화. **VOC가 로드맵에 반영되게.**

## 4. 미응답 문의 → 추천 답변 초안 (반자동)
- 아직 답이 안 달린 문의엔 **추천 답변 초안**을 작성한다: 사실 기반·정중·회사 톤.
- **초안만 만든다 — 사람이 검토 후 발송.** 답을 모르면 지어내지 말고 "확인 필요(담당 확인)"로 남긴다.

## 원칙
없는 목소리 지어내기 금지 · 소수 의견 과일반화 금지 · 왜/근거 · **최종 발송·확정은 사람**.
