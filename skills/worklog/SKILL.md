# 개인 업무일지 & 성장 코칭 (🔒 로컬 전용)

신입은 "뭐 했는지·뭐 할지"를 스스로 챙기기 어렵다. AI가 먼저 써주되, **검토·코칭으로 성장**시킨다. 남에게 안 보이는 개인 기록이다.

## ⛔ 프라이버시
저장은 `~/.pm-copilot/worklog/`(로컬 전용). 어떤 채널로도 전송·공유하지 않는다.

## 소스 (여기서 긁어온다)
- **연동 툴**(커넥터 연결 시): Jira/Linear 티켓 이동·코멘트, 노션 편집, 슬랙·메일. 없으면 있는 것만.
- **클로드 대화내역**: 오늘 Claude Code에서 한 작업을 세션 내역에서 재구성 — 세션 관리 도구(`list_sessions` / `search_session_transcripts`)로 "오늘 뭘 했는지"를 확인해 '한 일'에 반영. (미지원이면 사용자에게 물음)
- **플러그인 내부**: 오늘 브리핑, [[decision-log]], [[private-backlog]].
- **사용자 말**: "이거 했어/할 거야" 하면 즉시 기록.

## 1. 오늘 할 일 / 한 일 (하루 몇 차례 갱신)
```bash
pm-copilot worklog --todo "이탈 퍼널 계측 스펙 마무리"
pm-copilot worklog --done "경쟁사 리서치 3건 정리"
pm-copilot worklog --show          # 오늘
```
- 세션 시작(프로액티브 훅)·요청 시·정기적으로 소스를 훑어 **한 일은 자동 추가**, **빠진 할 일은 제안**한다.
- 각 '한 일'은 사실 기반(근거: 티켓/문서/대화). 추측 금지, 모르면 확인.

## 2. 하루 마감 — 검토 & 코칭 (성장의 핵심)
**자동으로 쓰기만 하면 안 된다.** 마감 때 본인이 고치고, 왜 했는지 알고, 배우게 한다:
1. **요약**: 오늘 한 일을 3줄로 + "오늘의 성과 1개".
2. **검토(코칭)**: 사수 시선 — 임팩트 큰 일 vs 시간 대비 낮은 일, 놓친 우선순위, 반복 패턴. **각 지적에 '왜'**.
3. **성장 포인트 1개**: 내일 바꿀 것 하나(예: "할 일에 성공 기준부터 붙이기").
4. **사용자 확인**: "이 요약·평가 맞아요? 고칠 것?" — 사용자가 수정·확정하게 한다. 수동적으로 두지 않는다.

## 3. 금주 / 월간 (재활용 — 쌓아두는 기록 아님)
```bash
pm-copilot worklog --show week    # 최근 7일
pm-copilot worklog --show month   # 이번 달
```
일일 기록을 모아 주간/월간 회고를 만든다 → [[weekly-review]]와 연결. **작업물은 다음 일에 다시 쓴다:**
- 반복 등장한 할 일 → [[prioritize]] 로 우선순위화
- 중요한 결정 → [[decision-log]] 로 이관
- 미룬 아이디어 → [[private-backlog]] 로
- 월간 성과 → 1on1·평가·이해관계자 보고 초안([[stakeholder-update]])으로 재사용
- 축적된 일지 → [[daily-brief]]·[[product-review]]의 컨텍스트로

## 원칙
사실 기반·근거 표시 · 왜를 설명 · 검토는 코칭(비난 아님) · **최종 확정은 사람**(고치고 이해하고 활용) · 로컬 전용(공유 안 함).
