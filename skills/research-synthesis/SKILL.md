# 유저 리서치 종합

흩어진 유저의 목소리를 **의사결정 가능한 인사이트**로 만든다.

## 1. 입력 받기 & 데이터 경계
- 인터뷰 노트/설문 응답/CS 티켓/리뷰를 받는다(붙여넣기·파일·커넥터: Intercom 등).
- **데이터 경계:** 유저 개인정보(이름·연락처)가 있으면 **익명화**해 다루고, 결과물에 PII를 남기지 않는다. 민감 원자료는 로컬에서만 처리.

## 2. 종합 방법
1. **코딩(태깅):** 언급을 주제별로 묶는다.
2. **테마 추출:** 반복되는 문제/욕구/장애물을 테마로. 각 테마에 **빈도**(몇 건/몇 명)와 **대표 인용 1~2개**.
3. **세그먼트 차이:** 특정 사용자군에서만 강한 신호가 있으면 구분.
4. **편향 주의:** 표본이 작거나 한쪽에 치우쳤으면 **명시**한다. "N=6, 전원 파워유저" 식으로.

## 3. 출력 구조
1. **핵심 인사이트 Top 3~5** — 각 인사이트에 근거(빈도·인용)와 **왜 중요한지**.
2. **테마별 상세** — 빈도순, 대표 인용 포함.
3. **놀란 점 / 가설과 달랐던 것** — 기대와 어긋난 신호.
4. **시사점 → 액션** — 로드맵/스펙에 주는 함의. `write-spec`·`prioritize`로 연결 제안.
5. **한계** — 표본·방법의 한계와, 더 확인할 것.

## 원칙
- **없는 목소리를 지어내지 않는다.** 인용은 실제 자료에서만. 요약은 원자료보다 짧고 다르게.
- 상관을 인과로 과장하지 않는다. 소수 의견을 전체로 일반화하지 않는다.
- 왜 이 테마가 중요한지, 근거가 얼마나 강한지 정직하게.
