> **작업 흐름(항상):** 왜(목적·의도) → 무엇을 → 어떻게 → 기존 컨텍스트·리서치 → 기획 → 시각화 → 호출·실행 → 🔁회고·보완. 자세히 [[method]].

# 제품 소개 영상 (스크립트 · 스토리보드)

이 스킬은 **영상을 렌더링하지 않는다.** PM이 제작팀·영상 생성 툴에 넘기는 **설계 문서**(스크립트 + 씬별 스토리보드)를 만든다.
"어떤 장면을, 왜, 몇 초 동안, 무슨 자막·나레이션으로" 가 확정된 콘티가 산출물이다. 실제 생성/편집은 사람 몫이다.

## 0. 대원칙 (항상 지킬 것)

- **(a) 각 씬·각 결정에 '왜'를 사람 말로.** "여기서 왜 이 화면인가 / 왜 이 순서인가"를 한 줄로 남긴다.
  근거 없는 장면은 "예뻐 보여서"가 되고, 그런 컷은 본생산에서 제일 먼저 잘린다.
- **(b) 수치·주장엔 출처.** "성인 71%가…", "전환율 3배" 같은 자막·나레이션은 반드시 출처를 단다.
  없으면 지어내지 말고 **⚠️ 확인 필요**로 표기 → 사람이 채우거나 뺀다. 광고 표현 규제(치료·완치·1위·최고 등)도 [[market-radar]]/컴플라이언스로 사전 점검.
- **(c) 반자동 — AI는 초안, 결정·발행은 사람.** 클로드는 스크립트·콘티·샷 지시 초안까지. **컨셉 확정·본생산 발주·업로드 공개는 사람이** 한다.
  본생산 전 **테스트 컷 2~3개로 톤을 먼저 검증**하는 순서를 권한다(한 번에 60초 다 뽑지 말 것).
- **(d) 신입이면 코칭 한 줄.** 예: *"영상은 '기능 나열'이 아니라 '한 사람의 상황 → 해소'다. 핵심 메시지 1개를 못 고르면 그 영상은 이미 진 거예요."*

## 1. 먼저 확정할 브리프 (여기서 막히면 콘티로 못 넘어간다)

씬을 짜기 전에 이 6개를 사람 말로 채운다. 비면 [[research]]로 컨텍스트를 먼저 모으고, 그래도 모르면 **묻는다**(추측 금지).

| 항목 | 왜 필요한가 | 예 |
|---|---|---|
| **왜(목적)** | 이 영상으로 뭘 바꾸려는가 — 인지? 신청? 투자검토? | "업계 관계자에게 '실행하는 AI'로 각인" |
| **타깃 1명** | 누가 보나에 따라 톤·근거·CTA가 다 바뀐다 | 소액 광고주 / 업계관계자 / 투자자 |
| **핵심 메시지 1개** | 영상은 하나만 남기면 성공. 2개 이상이면 0개 됨 | "대행료 0원, 성과의 5%만" |
| **러닝타임** | 30/60초로 구조 밀도가 갈린다(§4) | 60초 |
| **상영 환경** | **무음 재생 여부**가 자막 설계를 결정(§5) | 부스 루프(무음) / 세션 상영(유음) / 유튜브 |
| **톤** | 신뢰형·발랄형·다큐형… 레퍼런스 영상 1~2개로 고정 | "담백한 다큐 + 마지막 한 방" |

> 브리프가 서면 [[write-spec]]/[[plan-doc]]의 목적·성공지표와 어긋나지 않는지 대조한다(영상은 상위 기획의 하위 산출물).

## 2. 표준 구조: 훅 → 문제 → 해법 → 데모 → CTA

각 블록에 **'왜 여기에 이게 오나'**를 달아 둔다. 순서를 바꾸면 설득이 무너진다.

- **훅 (0~3초)** — *왜: 스크롤·시선을 멈추는 첫 줄.* 통계 한 방, 도발 질문, "이거 나잖아" 상황. 로고부터 띄우지 않는다.
- **문제 (공감)** — *왜: 시청자가 자기 고통을 먼저 봐야 해법이 값어치를 가진다.* 타깃의 실제 상황 1개.
- **해법 (제품)** — *왜: 문제의 정확한 반대편에 제품을 놓는다.* 핵심 메시지 1개만. 기능 나열 금지.
- **데모 (증거)** — *왜: 말보다 보여주기.* 실제 화면·전후 비교·결과물. 여기서 [[mockup]]/[[simple-design]]로 화면 컷 시안을 만들 수 있다.
- **CTA (1개)** — *왜: 본 다음 뭘 하라.* 행동 하나 + 도달 경로. 예: "AI 광고 실행 신청 → imagefactory.co.kr/adops".
  ⚠️ **링크·경로가 실제로 살아있는지 확인 필요**(영상에 구워지면 못 고침). 랜딩이 없으면 문의 채널로 대체하거나 링크 없이 마무리.

## 3. 씬별 스토리보드 (핵심 산출물)

컬럼 고정: **씬 · 길이 · 화면(비주얼) · 나레이션(V.O.) · 자막(온스크린) · 목적(왜)**.
길이 합이 러닝타임과 맞는지 항상 검산한다.

```
| 씬 | 길이 | 화면(비주얼) | 나레이션(V.O.) | 자막(온스크린) | 목적(왜) |
|----|------|--------------|----------------|----------------|----------|
| S1 훅 | 0:00–0:03 | (무슨 장면·앵글·움직임) | (있으면. 무음 상영이면 비움) | (무음이어도 서사가 서는 짧은 문구) | 시선 정지 |
| S2 문제 | 0:03–0:12 | … | … | … | 공감·고통 인식 |
| S3 해법 | 0:12–0:25 | … | … | … | 핵심 메시지 각인 |
| S4 데모 | 0:25–0:50 | … | … | … | 증거 제시 |
| S5 CTA | 0:50–1:00 | 로고 + CTA 버튼 | … | 행동 문구 + 링크 | 행동 유도 |
```

- **나레이션 vs 자막을 겹쳐 읽지 말 것.** 나레이션이 답을 다 말해버리면 자막이 같은 말을 반복해 지루해진다(과거 산출물의 반복 함정). 역할을 나눈다.
- **인물 발화(립싱크) 컷은 신중히.** 한국어 AI 립싱크는 아직 불안정 → 나레이션 + 인서트 컷 구조가 안전하다(과거 실제 선택).
- 화면 칸에는 나중에 **샷 생성 프롬프트**로 확장할 수 있게 앵글·톤·핵심 오브젝트를 구체적으로. (프롬프트 세트는 컨셉 확정 후 별도로.)

## 4. 30초 vs 60초 (같은 스토리, 밀도가 다름)

- **60초**: 5블록 다 넣고 데모(S4)에 시간을 준다. 세션 상영·유튜브·IR 데모용.
- **30초**: 문제·데모를 각 1컷으로 압축, 훅과 CTA는 유지. 소셜 피드·프리롤용. **핵심 메시지·CTA는 절대 안 줄인다.**
- 두 버전을 만들 땐 **60초를 정본으로 먼저 완성 → 30초는 컷 삭제로 파생**. 따로 쓰면 톤이 갈린다.

## 5. 톤·자막 규칙

- **무음 재생 대비: 자막만으로 서사가 완결돼야 한다.** 부스 루프·피드 자동재생은 소리가 꺼져 있다 — 소리 없이도 훅→해법→CTA가 읽히게.
- 자막은 짧게(한 줄 원칙), 화면당 하나. 광고체·과장 표현 금지, 규제 표현(§0-b) 회피.
- 톤은 레퍼런스 영상으로 고정하고, 컨셉이 갈릴 땐 A/B 두 안을 만들어 [[decision-log]]에 "왜 A안"을 남긴다.

## 6. 산출물 저장 (제안만)

문서를 `~/.pm-copilot/data/docs/` 에 **날짜-유형** 이름으로 저장하도록 제안한다(사람이 확인 후 저장). 예:

```
~/.pm-copilot/data/docs/2026-07-26-product-video-이미지팩토리60초.md
```

한 파일에 **브리프 + 5블록 스크립트 + 씬 테이블 + (있으면)30초 파생 + 오픈이슈(⚠️ 확인 필요 목록)**를 담는다.
※ 이 스킬은 문서 작성 전용이라 실행 스크립트·셸이 필요 없다. 렌더링·업로드는 사람/제작툴이 별도로 한다.

## 7. 🔁 회고·보완

- **본생산 전**: 테스트 컷 2~3개로 톤 검증 → 어긋나면 콘티부터 수정(비용 큰 본생산 전에).
- **발행 후**: 조회·시청유지율·CTA 클릭을 [[metrics-report]]로 회수해 "훅이 3초에 이탈을 잡았나 / CTA가 눌렸나"를 다음 영상 브리프(§1)에 반영한다.
- 반복되는 판단(톤·구조 선택)은 [[decision-log]]에 남겨 다음번에 다시 싸우지 않는다.
