# 런치 레디니스 체크리스트

"만들었으니 내보내자" 전에, 놓치면 사고 나는 것들을 사수처럼 짚는다.

## 1. 대상 파악
무엇을 언제 출시하는지, 규모(전체/부분 롤아웃)를 확인한다. 컨텍스트/스펙이 있으면 읽는다.

## 2. 게이트 점검 (각 항목: ✅ 완료 / ⚠️ 미흡 / ❌ 없음 + 근거)
1. **성공/실패 판정** — 성공지표·가드레일 정의됐나? **계측(이벤트)** 심겼나? 없으면 "출시해도 좋아졌는지 모른다".
2. **롤백 계획** — 문제 시 되돌리는 법과 기준이 있나? 피처플래그?
3. **QA / 엣지케이스** — 핵심 흐름 + 에러/빈 상태/권한/데이터 없음 확인?
4. **개인정보 · 법무 · 보안** — 수집 데이터 동의/고지, 약관, 보안 리뷰 필요 여부.
5. **접근성** — 키보드/스크린리더/대비 등 최소 기준.
6. **고객지원 / 공지** — CS 안내, 릴리즈 노트/공지, FAQ 준비?
7. **실험 설계(해당 시)** — A/B 대조군·표본·기간·판정 시점 정해졌나?
8. **의존성** — 다른 팀/서드파티/인프라 준비 상태.

## 3. 출력
- **레디니스 요약** — 지금 나가도 되나(Go / Go with risks / No-go)와 **그 이유**.
- **막는 것(Blocker)** — ❌ 항목 우선, 각 항목에 "지금 할 수 있는 한 수".
- **출시 후 볼 것** — 첫날 모니터링할 지표/알림.

## 원칙
- 통과시키려고 관대하게 넘기지 않는다. 없는 건 없다고. **왜 위험한지** 설명하고 다음 수를 준다.
- 깊은 검토가 필요하면 `ask-sunbae`로 넘겨 반박 검토.
